# How the site works · for whoever maintains it

A static site (HTML, CSS, plain JavaScript) on GitHub Pages. No framework and no build step at run time:
the build scripts only regenerate data files, which are committed. Everything a page needs is in this repo,
except the optional services listed under [Outside services](#outside-services).

## The pages

| Page | What it is | Built from |
|---|---|---|
| `index.html` | Home | static HTML + the tool cards from `content/pages.js` |
| `n8n.html`, `english.html` | The two 24-week journeys and their reference sections | static HTML + `assets/js/*-data.js` + `assets/js/journey.js` + the week files |
| `review.html` | Spaced review (FSRS), mistakes notebook, stats, backup | sections (`content/sections/review.js`) + `assets/js/review.js` |
| `lab.html` | Workflow viewer/checker, template search, playgrounds | sections + `assets/js/lab.js`, `assets/js/lab-expr.js` |
| `speak.html` | Pronunciation, shadowing, dictation, work situations | sections + `assets/js/speak.js` |
| `prompts.html` | Prompt library, prompt course, my prompts | sections + `assets/js/prompts.js` |
| `sheets.html` | Printable cheat sheets | sections only |

Every page loads, in this order: `i18n.js` → the English dictionaries → `content/pages.js` → `config.js` →
`site.js` → (page data and app) → `ui.js` → Supabase → `account.js`.

## The shared pieces

| File | Job |
|---|---|
| `assets/js/i18n.js` | Arabic/English switch. `T()`, `TF()`, `TDEEP()` translate Arabic source text through the dictionaries; `{ar, en}` values pick the language directly. `I18N.bi(s)` gives `{ar, en}` for a dictionary string. |
| `content/pages.js` | **The list of pages.** The top menu, the «More» menu, the footer, the home page cards and the search all read it. |
| `assets/js/site.js` | The shell: menu and footer, site search (Ctrl+K or `/`), deep links (`#section?q=…`), stores + sync hooks, mistakes notebook, activity/streak, backup, speech, giscus comments, GoatCounter, service worker registration. Everything is on `window.SITE`. |
| `assets/js/sections.js` | Builds a page from data (see below). |
| `assets/js/ui.js` | Font size, collapsible sections, and following deep links (fills a section's search box or finds the card). |
| `assets/js/journey.js` | The 24-week engine: unlock rules, day view, tests, exams, certificate. Emits `journey:change` / `journey:attempt`, records wrong answers with `SITE.mistake()`, opens `#journey?w=5&d=2`. |
| `assets/js/account.js` | Optional sign-in by email link (Supabase) and sync of the journey progress, test attempts and every `SITE` store. |
| `sw.js` | The offline app. Generated by `tools/build_sw.js`: the shared shell (~420 KB) is kept on the first visit; each page's data when it is first used; everything (with the 48 weeks) when the learner presses «Download the whole site» on the review page. |

### Stores (the data a learner creates)

`SITE.get(key)`, `SITE.setItem(key, id, item)`, `SITE.removeItem(key, id)`, `SITE.items(key)`.
A store is a map `{id: {…, at}}` in `localStorage` under `site_<key>`. A removed item stays as `{del: 1, at}`,
so removals sync too. Merging keeps the newer `at` per id (`SITE.merge`).

The synced keys are `SITE.SYNC_KEYS`: `srs` (review schedule), `mistakes`, `lab` (solved challenges),
`prompts` (my prompts), `fav` (starred cards), `speak` (best scores), `done` (finished lessons).
To sync a new store, add its key there — `account.js` does the rest (table `user_store`, one row per key).

Other keys: `journey_<track>_v1` (journey progress, synced as `progress`), `eng_plan_v1` / `n8n_plan_v2`
(the reference sections), `site_activity`, `site_review_log`, `site_review_prefs`, `site_lab_draft`,
`site_lang`, `site_zoom`, `site_open_<page>`, `eng_voice`. The backup (review page) exports all of them.

## Pages built from sections

A tool page is an HTML shell (generated from `tools/page.template.html`) plus a content file that adds sections:

```js
SECTIONS.add({
  page: 'prompts',            // the page id (content/pages.js)
  id: 'library',              // the section id = its link: prompts.html#library
  order: 1,
  kind: 'pr',                 // optional: put the items in the site search (see KINDS in site.js)
  title: { ar: '…', en: '…' },
  nav: { ar: '…', en: '…' },  // optional short name for the section bar
  desc: { ar: '…', en: '…' }, // small markdown: `code`, **bold**, [link](https://…), lists
  type: 'cards',              // cards | lessons | sheets | a type a page script adds
  // …the type's own fields
});
```

### Built-in types

**`cards`** — searchable cards with category tabs and favourites.
Section fields: `cats: [{id, t}]`, `items`, optional `searchHint`, `saveLabel` (shows a button that emits `sections:save`).
Item fields: `id`, `cat`, `lvl` (`b`/`i`/`a`), `t`, `body`, `code` (text to copy; `{{name}}` becomes a box to fill —
n8n expressions such as `{{ $json.x }}` are left alone), `vars: {name: {ar, en}}`, `tip`, `bad` + `badWhy`
(a weak version to compare), `links: [{t, url}]`, `tags`, `rtl`.

**`lessons`** — numbered lessons, one open at a time, with a «done» mark (store `done`).
Item fields: `id`, `t`, `min`, `body`, `example` (shown as code), `try`, `links`.

**`sheets`** — printable sheets. Item fields: `id`, `t`, `sub`, `groups: [{t, rows: [[code, meaning]]}]`.

### A page type of your own

```js
SECTIONS.type('mytype', function(el, sec){ el.innerHTML = '…'; });
```

Put it in `assets/js/<page>.js` and list that file in the page's `scripts` in `content/pages.js`.
Use `SITE.B('عربي', 'English')` / `SITE.L({ar, en})` for text, so no dictionary work is needed.

## Adding a new tab (a page)

```bash
npm run new:page -- tools-x "أدوات جديدة" "New tools"
# → tools-x.html, content/sections/tools-x.js (one example section), and its entry in content/pages.js
```

1. Edit `content/sections/tools-x.js` (and the `icon`/`desc` of its entry in `content/pages.js`).
2. `npm run build` (search index + offline list), then `npm test`.
3. Add its checks to `tools/smoke_pages.js` (the `checks` object) if it has its own interactions.

After changing `tools/page.template.html`, rewrite every tool page with `node tools/new_page.js --all`.

## Build, test, release

| Command | Does |
|---|---|
| `npm run build` | Builds the week files from `content/<track>/src`, the search index and review deck (`assets/data/`), the sharing tags of every page + `sitemap.xml` (`tools/build_meta.js`), and `sw.js` |
| `npm test` | Old pages in both languages (jsdom), journey rules, content validation, every lab challenge against its solution (Python through the local `python`), the tool pages and the search |
| `npm run release` | Bumps `?v=` on every page (`tools/bump_version.js`), builds, tests |
| `npm run links` | Checks every external link → `tools/links-report.md` (also runs every Monday on GitHub) |
| `npm run a11y` | Accessibility audit (axe-core) of every page in Chrome; fails on any serious or critical violation (it was brought to zero on 2026-09-30) |
| `npm run e2e` | Opens every tool page in a real Chrome (Playwright): Python, SQL, workers, the offline app, the template search, phone layout; screenshots in `tools/e2e-shots/` |
| `npm run new:page` | See above |
| `npm run i18n:missing` / `i18n:apply` / `i18n:build` | Dictionary work for Arabic strings in the old pages (see README) |

GitHub Actions: `.github/workflows/test.yml` runs the build (it fails if the generated files are not committed)
and the tests on every push; `links.yml` checks the links weekly.

**Release checklist:** `npm run release` → look at the pages locally (`npm run serve`) → commit → push to `main`
(GitHub Pages publishes it in about a minute).

## Outside services

| Service | Used for | When |
|---|---|---|
| Supabase (`config.js`) | Optional accounts and sync | only after sign-in |
| cdn.jsdelivr.net | Luxon (expressions), Pyodide (Python), sql.js (SQL) | only when the lab runs that language |
| api.n8n.io | Template search | only when searching templates |
| The browser's speech recognition (Google in Chrome) | Pronunciation scoring | only when you press 🎙 |
| giscus.app (`config.js`) | Comments as GitHub Discussions | only when a discussion box is opened |
| GoatCounter (`config.js`) | Visit counts, no cookies | only when a code is set (empty by default) |
| Google Fonts | Fonts | every page |

## Things that must stay true

- Arabic is the source text; every visible string has English too (`npm test` fails on Arabic left in English mode).
- Only free or official resources are linked; no copied book content; examples are written for this site.
- Secrets never go in the repo. The Supabase key in `config.js` is the public (publishable) key; row-level security protects the data.
- No age-group pages.
